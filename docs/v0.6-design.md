# dsh-notifier v0.6 设计稿:开放事件源(插件间通知总线)

> Historical design record for the pre-`0.7` public contract. It intentionally records the then-current full-payload event and directed-send behavior. For the current consumer contract, read `PLUGINS.md`; for the security migration, read `docs/security/PLUGIN_SECURITY_FIX_PLAN.md`.

> 状态:评审后修订稿 v2(两轮独立审查,记录见附录;阻塞项已全部裁定)。
> 前置讨论:v0.5 发布后架构评估(允许度结论:核心管线零改动,只差开放面)。
> 版本主题:**dsh-notifier 从「DSH 的通知插件」升级为「DSH 生态的通知基础设施」**——其他插件一行注入即可推送,一行监听即可订阅。

## 0. 目标与非目标

### 目标

1. **出向开放**:其他插件(dsh-email、定时任务、CI 面板……)通过宿主服务注入调用我们推送,共享全部基础设施(配置、路由、分段、限流、账本、flush)。
2. **入向开放**:其他插件可订阅我们每次广播的结果事件(送达/跳过/失败明细),用于指标采集、桌面客户端、二次路由等。
3. **零存量回归**:673 个存量测试断言一条不改(审查裁定后收窄,见 §3.3/§3.5);我们不可用时消费方也不许崩(no-op stub 军规外延)。
4. **可审计、可治理**:外部推送带来源标注**落账本**(v2:含 ledger 改动);按源独立限流;吵闹的源将来可一键静默。

### 非目标(明确不做)

- **不做进程间/跨机开放**:不监听端口、不加 IPC——宿主内插件间就够,跨机走 webhook 渠道(已有 27 渠道)。开放面攻击面仅限宿主进程内,与 `inject: ['tools']` 同级信任。
- **不做任意入站事件转发**:消费方只读订阅,不能借我们向 DSH 注入事件。
- **不改动 notify 工具语义**:模型侧 `notify` 工具的限流、渲染、错误反馈一概不动。
- **v0.6 只发 `sent` 一种事件,source 只覆盖 `plugin` 一路**:`tool`/`event`(自动推送线)、`approval`、`digest` 路径的 source 与 `heartbeat`/`stall`/`approval-decided` 事件一并列为 v0.7(tool 线裁定:实施时发现「notify 工具分流」4 处存量测试同样对第二参做全形状断言,与 §0-3 军规冲突,同 event 线裁定缓发——设计稿 v2 审查时漏检)。
- **不做动态注册渠道**:消费方不能运行时注册新适配器(ADAPTERS 静态表是 CI 漂移检查基线)。

## 2. 特性 A:出向服务注入 `ctx.notifier`

### 2.1 服务面(消费方视角,先定契约再写实现)

```js
// 消费插件示例(v2:防御式配方——回调式注入为主,能力探测为辅;version 相等比较是陷阱,弃用)
export const inject = ['notifier']

export function apply(ctx) {
  // 首选:回调式注入(cordis 原生晚绑定——服务就绪即回调,不依赖加载时序)
  ctx.inject?.(['notifier'], (notifier) => {
    if (typeof notifier?.push !== 'function') return // 能力探测,不做 version 相等比较
    notifier.push({ title: '📧 新邮件', content: '来自 x@y.z:周报初稿', level: 'active' }, { sourceName: 'dsh-email' })
      .then((r) => ctx.logger.info('送达', r.delivered))
  })

  // 兜底:ctx.inject 不存在时的探测式(宿主语义验证后二选一,PLUGINS.md 定稿)
  if (typeof ctx.notifier?.push === 'function') { /* 同上 */ }

  // 订阅广播结果(特性 B)
  ctx.on?.('dsh-notifier/sent', (record) => { /* 监听器必须 O(1),重活自查排队;禁止在监听器内 push(循环军规) */ })

  // 卸载前 flush:apply 期捕获引用,防服务清除时序踩空(审查 R12)
  const notifier = ctx.notifier
  ctx.on('dispose', () => { notifier?.flush?.() })
}
```

- **定向推送**(可选):`push(msg, { channel: 'bark' })` 走单渠道路径。**诚实声明**:该路径现状不进账本、不发 sent 事件(盘点 #4),仅凭返回值知晓结果;v0.6 不改此行为(§3.3 裁定)。
- **返回值契约(v2 新增,never-reject)**:`push` 永不 reject。内部异常返回 `{ ok: false, delivered: [], skipped: [], failed: [{ reason: 'internal' }], source }`。消费方不写 try-catch 也不崩。
- 广播返回值与 onSend record 同构外加 `source` 字段(facade 拼合,**不改 notifyAll 返回值**——`notify.test.mjs:110` 全形状 deepEqual 守着);定向返回值由 facade 把 `channelResult` 适配成 outcome 形状(盘点 #11)。

### 2.2 新模块 `src/public.mjs`(facade,~140 行)

```js

export function createPublicFacade({ ctx, notifier = null, config = {}, logger = null } = {}) {

  //   anonymous 表外常驻单窗,不参与淘汰
  // push(msg, options = {}, meta = {}) 全 catch(never-reject):

  //   2. 长度钳制(v2 新增,审查 S2):title/content 各 20000 码点,超出截断 + warn(防 1MB content → 850 段风暴;

  //   3. 双空(title==='' && content==='')→ 返回 skipped:['(malformed)'],不推不 emit 不占限流名额

```

### 2.3 source 的流转(v2:范围收窄)

- `notifyAll` 增加 `sendOptions.source`,**只并入 onSend record,不动返回值**(盘点 #3/#11,`notify.test.mjs:110` 守)。
- facade 广播:facade 自行把 source 拼进返回值——notify.mjs 返回值形状不变。
- **缓发**:tool 线(`tool-register.mjs`)、event 线(event-listener)、approval、digest 的 source 一律 v0.7(裁定见 §3.5)。

### 2.4 按源限流

- 复用 `createRateLimiter`,每源独立滑动窗,默认 `limitPerMinutePerSource: 10`(对齐工具默认,`config.public` 可调,0=不限)。
- 超限返回 `{ ok:false, skipped:['(rate-limited)'] }`,**emit 照发、账本照记**(静音不等于没发生)。
- LRU 淘汰时对被逐源 warn(淘汰即重置限流窗,轮换 sourceName 绕限流的成本显性化);anonymous 常驻表外单窗。

## 3. 特性 B:入向事件发射 `dsh-notifier/sent`

### 3.1 事件契约(payload 视为只读约定)

```js
ctx.emit('dsh-notifier/sent', {
  time: 'ISO', message: { title, content, level, group },
  ok: true, delivered: ['telegram'], skipped: [], failed: [{ type: 'bark', reason: '...' }],
  source: { kind: 'plugin', name: 'dsh-email' },  // v0.6 唯一路径;tool/event/approval/digest 为 v0.7(实施期裁定,见 §3.5)
})
```

- **深冻结(v2 升级,审查 D1)**:emit 前对 record、`record.message`、三个数组及其元素逐层 freeze——浅冻结挡不住 `record.delivered.push('fake')` 跨消费者污染;payload 是纯 JSON 形状,深冻结成本可忽略(hub 深拷贝先例,盘点 #13)。PLUGINS.md 给 `{...record}` 自拷贝配方。
- 事件名命名空间 `dsh-notifier/*`;v0.6 只发 `sent`。

### 3.2 emit 的防御性

- emitSend 单独 try-catch,不 await(fire-and-forget);**try-catch 防抛不防慢**——文档军规「监听器 O(1)」(审查 R16);若宿主无 emit,首次 TypeError 被吞后 warn 一次(可观测,审查 R6 补丁)。
- **emit 开关(v2 新增,审查 O4)**:`public.emit` 默认 true;false 时组合器不挂 emitSend——保留「admin 关闭零开销」家训的完整性。

### 3.3 发射点矩阵(v2:如实修正)

| 出口 | 触发 | emit | 账本 |
|---|---|---|---|
| notifyAll 正常路径 | 每次广播后(含部分失败) | ✅ | ✅ |
| notifyAll quiet 路径 | `skipped:['(quiet)']` | ✅ | ✅ |
| notifyAll 零渠道 | `delivered:[]` 直接返回 | ❌(现状不调 onSend) | ❌ |
| facade 限流拦截 | `skipped:['(rate-limited)']` | ✅(facade 直发) | ✅(facade 直记) |
| facade malformed | 双空输入 | ❌(调用方错误,返回值可见) | ❌ |
| 单渠道 notify() | 工具定向 / facade 定向 | ❌(**现状无 onSend,v0.6 不改**——改则单渠道工具推送突然进账本/SSE,违零回归) | ❌ |

### 3.5 裁定记录(v2 审查阻塞项 3;v3 实施期扩展)

**event 线 source 缓发 v0.7**。理由:`wiring.route.test.mjs:394/426` 对 event-listener→notifyAll 第二参做全形状 deepEqual,补 source 必炸存量断言;三选项中「改断言」违 §0-3 红线,「装配层包装注入」复杂度不成比例,**缓发最诚**。连带:`source.kind` 契约 v0.6 只有 `plugin`,§3.1 已如实标注;approval/digest 路径同理缓发(审查 R15)。

**tool 线 source 缓发 v0.7(v3 实施期裁定)**。实施时发现「notify 工具分流」4 处存量测试(`execContext.agent.id 存在时收到 channelTypes` 等)同样对工具广播第二参做全形状 deepEqual——tool 线补 source 与 event 线是同类冲突,v2 审查时两 agent 均漏检(误判「工具测试桩只读第一参」)。按同一军规裁定缓发,v0.6 的 `source` 收敛为纯 `plugin` 一路。

## 6. 兼容性影响(v2:三态表)

| 状态 | ctx.notifier | 消费插件(按 cordis 语义) |
|---|---|---|
| 顶层 `enabled: false` | **仍提供 no-op stub**(v3 spike 修正:服务缺失会阻塞宿主启动→启动 abort,绝不能不提供) | push 返回 `skipped:['(disabled)']`,flush 即 resolve——不崩、宿主照常启动 |
| `public.enabled: false`(默认 true) | 注入 no-op stub | 同上 |
| 零渠道 | 注入真 facade(推送自然返回 `delivered:[]`) | 同上 |
| 正常 | 注入完整 facade | — |

> v3 注:spike 验证宿主对 `inject: ['notifier']` 的消费插件有**启动期强制**——服务不 truthy 则该插件 pending,任一 entry 未激活 → 宿主整体 abort。因此「不提供服务」在任何形态下都是不可接受的;三层都提供(stub 兜底)是本设计的硬约束。消费方若想「可选依赖」(dsh-notifier 缺席也能启动),用 `ctx.inject?.(['notifier'], cb)` 回调式而非静态 inject 声明(PLUGINS.md 详述)。

- **默认开启服务注入**是行为增量(与 v0.5「stall 默认开」同构):0.x minor 允许 + CHANGELOG 置顶显著标注;10/min/源限流 + 长度钳制兜底。
- record 新增 `source`、账本 entry 新增 `source` 均为**加法**,旧读取方(摘要、admin UI 只读固定字段)无感;`notifyAll` 返回值形状不变(`notify.test.mjs:110` 守)。
- **安全面诚实声明(审查 S6)**:sent 事件 payload 含完整通知正文(可能含审批摘要、邮件内容),**任何已加载插件都可订阅全量通知流**——信任域与 `inject: ['tools']` 同级,进程内无边界;文档写明,不隐瞒。
- 服务名 `notifier` 占用全局单槽(cordis 服务无命名空间惯例,tools/agents 先例);双实例共存时后写者覆盖、先写者 dispose 引用比对不清空(§2.5),PLUGINS.md 声明占用。
