# ROADMAP.md — dsh-notifier 战略路线图

> 更新：2026-09-13 · 基线版本 v0.10.2（1616 tests）
> 本文是**产品战略**路线图（做什么、为什么、什么时候），技术形态演进见 [architecture-roadmap.md](architecture-roadmap.md)。

## 定位与竞争格局

| 赛道 | 占位者 | 我们的选择 |
|---|---|---|
| IM 聊天入站（把手机变成聊天窗口） | dsh-im（1283⭐，官方认可） | **不正面进入** |
| 手机同屏访问 | dsh-pocket（1095⭐） | **不进入** |
| 通知出站 + 手机遥控（把手机变成遥控器/告警中心） | **dsh-notifier** | **主场，做绝** |
| 生态公共通知层（其他插件的 `notify()`） | 空缺 | **卡位** |

核心叙事：dsh-im 解决「在手机上跟 agent 聊天」，dsh-notifier 解决「agent 主动找你、你在手机上拍板和接管」。两者可同装，不互斥。

## 战略主线（2026-09-13 所有者裁定）

**A + C 组合**：
- **A · 差异化深耕**：控制闭环深化（A1）+ 可靠性标签化（A2）
- **C · 生态卡位**：`ctx.notifier` 公共通知层完善（C1）+ 推广（C2）+ 升级经验回馈（C3）
- **D · 增长曝光**：暂缓，由所有者决定何时启动

明确放弃 B（流式聊天卡片、多机器人实例、入站渠道数量竞赛）——那是 dsh-im 主场，迭代速度（其 v4.20.x）不允许追赶，且会破坏零依赖轻量定位。

## 北极星指标

| 指标 | 口径 | 现状 |

| 生态消费方数 | 声明 `inject: ['notifier']` 的外部插件数 | 0 |

## 里程碑

### v0.11.0 — 公共面 SDK 化收尾（C1）

现状：`ctx.notifier` 服务（v0.6 起）+ PLUGINS.md 契约（公共面 v0.7）**已存在**。本版本补消费方体验的缺口：

| 工作项 | 内容 | 验收 |
|---|---|---|
| 消费方测试工具 | 新增 `dsh-notifier/testing` 子路径导出 fake notifier（消费方单测用，不必手写 stub） | 子路径纳入 package.json `exports`，契约测试覆盖 |
| 类型声明 | 为公共面（push/sent 事件/flush）提供 `.d.ts`，TS 插件可开箱 | `tsc --noEmit` 通过 |
| 最小示例 | `examples/consumer-demo/`：30 行示例插件，inject + push + 订阅 sent | 示例随 verify-release 做语法检查 |
| 双语契约 | 新增 `PLUGINS.en.md`（生态推广必须双语） | 与 PLUGINS.md 段落一一对应 |

**不做**：不改变公共面语义（`ctx.notifier.version` 保持 0.7，无 breaking）。

### v0.12.0 — 遥控闭环深化（A1）

现有：`/tasks`、`/use`、审批按钮/回复、心跳停止钮、`ask_user`。

| 工作项 | 内容 | 约束 |
|---|---|---|
| `/sessions` | 列出活跃会话与当前绑定，手机上可切换观察对象 | 仅配对身份可见 |
| `/log` | 回传当前会话最近 N 行输出 | **默认关闭**，需管理台显式开启；有界（行数/字节上限）+ 凭据脱敏 |
| 心跳策略模板 | quiet-hours、长任务阈值预设，管理台一键套用 | 不写 YAML |
| 审批策略模板 | owner-only / 全员可批，管理台切换 | 与成员系统现有作用域对齐 |

验收：命令矩阵测试新增分支；guide.md 同步；`/log` 的默认关闭与脱敏有契约测试钉死。

### v0.13.0 — 可靠性契约产品化（A2）

把 README 的口号变成第三方可验证的证据：

| 工作项 | 内容 | 验收 |
|---|---|---|
| docs/reliability.md | 每条承诺（不漏一回合 / 沉默永不批准 / 分档重试 / 单次裁决 / fail-closed）映射到具体测试文件与场景 | 文档与测试一一对应 |
| 可靠性契约包 | `test/reliability/` 独立目录聚合相关用例，可单独 `node --test test/reliability/` 运行 | CI 可单独调用 |
| 管理台健康面板 | 各渠道近期送达率 / 重试次数 / 最近失败原因（账本已有数据，只做展示） | 只读、本地、不新增外发 |

### v0.14.0 — 生态回馈与推广（C2/C3）

| 工作项 | 内容 | 验收 |
|---|---|---|
| 升级卡回馈 | 向 `oh-my-dsh/dsh-plugin-upgrade-skill` 提交 2~3 张真实迁移卡（静态 inject 裁定、`ctx.userQuestions` seam 桥接、QQ 网关心跳时序） | PR 被合并 |
| 生态邀约 | 给 2~3 个有出站需求的生态插件提 issue/示例 PR，邀请消费 `ctx.notifier` | 至少 1 个外部插件接入 |
| 收录描述收口 | awesome PR #4981 合并后，各目录站描述统一为「通知 + 遥控 + 生态通知层」定位 | 三处描述一致 |

## 节奏与发布纪律

- 版本语义遵循 [VERSIONING.md](VERSIONING.md)：功能 = minor，每里程碑一个 minor。
- 发布门禁不变：全量 tests + `verify-release` + channel-matrix + npm publish + `dev→main` 同步。
- 每个里程碑开工前先更新本文档状态列，收口后回写结果。

## 不做清单（防漂移）

1. 不做流式聊天卡片体验（dsh-im 主场）。
2. 不做单渠道多机器人实例。
3. 不新增入站渠道（维护成本 > 差异化收益；出站渠道按需可扩）。
4. 不做手机同屏/Web 远程桌面（dsh-pocket 主场）。
5. D 线曝光动作（LINUX DO 发帖、README 演示 GIF、博客投稿）暂缓，待所有者单独启动。

## 风险

| 风险 | 缓解 |
|---|---|
| C 线依赖外部插件作者愿意接入 | 示例 + 类型 + 测试工具三件套降低摩擦；主动投稿代替等待 |
| `/log` 回传的隐私面 | 默认关闭 + 管理台显式开启 + 脱敏 + 有界，契约测试钉死 |
| 竞品反向覆盖通知场景 | 可靠性证据包 + 生态层卡位是先发护城河，执行速度优先 |
