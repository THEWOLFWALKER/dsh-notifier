# dsh-notifier v0.14 Assumption Ledger

Every assumption the v0.14 code depends on that is **not** fully proven by automated tests or
current official source must be registered here.

Format per entry:

```markdown
## A-xxx — Short name

Claim:
Scope:
Why code depends on it:
Evidence level:   (unit-tested | contract-tested | source-verified | host-smoke-verified | provider-verified | real-device-verified | external-evidence-pending)
Evidence source/path:
Counterexample / risk:
Automated verification:
External verification (if any):
Fallback when false:
Owner module:
Status: open | verified | retired
```

Register an assumption when any of these hold:

- a Host API shape is not verified against current official source;
- there is an unknown between provider API success and client-side behavior;
- version guessing stands in for a feature probe;
- an undocumented field is relied upon;
- network / client behavior cannot be proven by a mock;
- cross-process / cross-restart ordering is assumed.

Related durable facts live in `docs/memory/risks.md` and `docs/compatibility-matrix.md`; this
ledger indexes the v0.14-relevant subset rather than duplicating them.

## A-001 — DSH user-questions waterfall is the current public answerer seam

Claim: For the declared DSH peer versions, questions are answered through the
`user-questions/request` waterfall (`ctx.waterfall(...)`), not through a `registerProvider()`
API.
Scope: `src/host/native-questions.mjs`, `src/questions/router.mjs`.
Why code depends on it: the native questions bridge attaches as a waterfall interceptor
(`{prepend:true, global:true}`) and keeps `registerProvider` only as a legacy/future probe.
Evidence level: source-verified (official source seam) + contract-tested (mock waterfall).
Evidence source/path: `deepseek-ai/deepseek-harness`
`packages/interaction/user-questions/src/index.ts` (re-check per S04); local contract tests in
`test/` for the interceptor.
Counterexample / risk: a Host that exposes a different `ctx.userQuestions` surface or only
`registerProvider` would not bridge; the plugin degrades to `unsupported`/fallback.
Automated verification: waterfall interceptor contract tests.
External verification: one real-host run recorded in `docs/memory/risks.md`
(2026-09-17 #27), not re-run on this codebase for v0.14.
Fallback when false: degrade to `unsupported` with a diagnostic; do not crash startup.
Owner module: `src/host/native-questions.mjs`.
Status: open (re-verify against current official source during S04).

## A-002 — Native surface revision uses `{epoch, revision}`

Claim: the Native refresh cursor is a `{epoch, revision}` pair so that process restarts cannot
be mistaken for continuation.
Scope: `src/control-surface/revision.mjs`, `client.js`.
Why code depends on it: stale-response rejection and generation handling rely on both fields.
Evidence level: unit-tested / contract-tested.
Evidence source/path: `src/control-surface/revision.mjs`, related tests.
Counterexample / risk: a bare revision compare across an epoch change would accept a stale
response.
Automated verification: revision / generation tests retained and extended in S13.
External verification: not required.
Fallback when false: reject responses whose epoch differs; treat as stale.
Owner module: `src/control-surface/revision.mjs`.
Status: verified (automated).

## A-003 — DSH Connection route ownership needs the webServer fallback

Claim: on the real `0.1.7-rc.2` web profile, `ctx.connection.rpc.handle` cannot own the
`/dsh-notifier` route because its owner context lacks the required `webServer` injection, so a
guarded fallback mounts the same authenticated envelope on the Host web server seam.
Scope: control-surface transport wiring.
Why code depends on it: the Native RPC route must exist on supported Hosts.
Evidence level: host-smoke-verified (0.1.7-rc.2) + source/artifact verified for the 0.1.7 family.
Evidence source/path: `docs/compatibility-matrix.md` (v0.12 Connection transport note).
Counterexample / risk: a Host that does allow `rpc.handle` to own the route may double-mount or
prefer a different carrier. Re-audit in S14 before any carrier change.
Automated verification: guarded fallback wired with admission/trust rules; headless profiles
degrade without crashing.
External verification: real host smoke recorded for rc.2 only.
Fallback when false: guarded fallback path; headless/no-webServer profiles degrade cleanly.
Owner module: control-surface transport.
Status: open (re-audit in S14).

## A-004 — Legacy channel keys are read-only migration input

Claim: legacy channel keys are read only as a migration source; new writes enter the canonical
authority and canonical wins on conflict.
Scope: `src/control-surface/channel-config-migration.mjs`,
`src/control-surface/outbound-config.mjs`, `src/inbound/channel-config.mjs`.
Why code depends on it: I12 migration correctness and the "no double authority" rule.
Evidence level: contract-tested.
Evidence source/path: channel-config migration tests.
Counterexample / risk: a legacy key that carries a value never migrated would be silently
ignored; a real historical state fixture may be missing (S13 should generate explicit fixtures
from repo tests/history rather than guessing old schemas).
Automated verification: migration idempotency / canonical-wins tests (extended in S01, S13).
External verification: none required.
Fallback when false: keep legacy read available; never delete legacy before canonical success.
Owner module: `src/control-surface/channel-config-migration.mjs`.
Status: open (fixtures to be hardened in S13).
