# 实施约束与决策

## 用户明确决定

- 只对齐新版本：本任务固定rc.5；不维持旧宿主的分支、版本探测和API兼容fallback。
- 旧数据不强求转换，重新配置/配对可接受。不自动删除用户目录，不从模糊旧身份恢复权限或动作。
- 排除旧dev代码及独立重写。先以当前main重建dev，再以dev交付各阶段；遵守DELIVERY-POLICY的备份、精确lease与读回检查。
- 允许代码、测试、构建、DSH运行；不使用真实provider/IM/LLM账号或真实设备。以前“仅静态”限制仅保留为历史阶段事实。

## 本任务采用的技术边界

- 暂不引入dsh-std；其工具/会话窄映射不能代替事件、控制、IM和仲裁核心。保持零强制运行依赖原则，必需开发依赖可以合理添加并锁定。
- 保留28出站/6入站的注册与配置范围；不因公开证据不足静默删渠道，不声称未验证能力可用。不可支持的特定模式给明确原因和替代路径。
- 保留出站群通知。入站不得放宽现有群控制限制；为保守收口，本任务设计默认不允许群会话执行控制/对话/敏感查询，所有入口使用同一政策。这是设计默认而非用户曾口头确认“全部功能只私聊”。变更应写入升级说明，不删群通知配置。
- Native通知与控制为日常入口，loopback Console为Recovery；保留宿主React/视觉语境，不做品牌和导航重设计，不要求特定蓝白色系。
- 保留ctx.notifier、既有导出及模型工具语义；移除旧宿主适配不等于任意破坏消费者接口。确需变更形状则同步types、消费者示例和版本说明。
- 新版本号在T27按实际破坏性范围确定；不要一开始锁死1.0或假装是无破坏patch。

## 安全与状态红线

- 一份业务Store、一套身份与路由、一套交互winner。不得native/std或UI/backend各建权威。
- 账号主键、会话/聊天授权、一次性令牌、过期与来源检查必须在副作用前生效；注册面命令有明确例外，不能所有slash直通。
- 不能通过删dedup或盲重试解决丢消息；外部结果未知不得伪造成失败可重发或成功已送达。
- 不打印token/secret、完整私聊内容或真实状态。测试凭据只用虚构内容；测试网络外发默认拒绝。
- Recovery继续127.0.0.1；Origin比较使用完整允许origin，不能以loopback/同站猜测放宽跨端口写请求。
- 不创建生产通用debug认证绕过、不把test injection作为部署默认。真实宿主测试应通过宿主正常认证，不伪造admit。

## 自主执行与停止条件

可在临时目录安装固定开发工具/宿主依赖、运行测试、浏览器和本地服务器；可本地分支提交。已有git身份保留，不改全局身份；不把附件推荐的作者名当用户授权。

允许初始重建dev及每阶段review/neat后普通push dev，细则见DELIVERY-POLICY；不merge main/tag/release/npm publish，不联系他人，不操作真实账号，不改全局DSH配置。遇测试失败持续修；普通工程选择自行决策并记录，不反复问维护者。阻塞仅限缺工具/网络/平台能力或真正冲突要求，记录具体尝试与替代，并继续独立任务。

缺macOS/Windows不能伪称通过；可运行的当前平台必须验证，其他平台用命令构造/注入测试且列明未执行。不得为保持漂亮测试数删有效测试、放宽安全断言或skip核心失败。
