## S01 — Channel single-writer convergence

### Pre-state found on dev

Outbound and inbound channel mutations were already *mostly* converged by v0.12.1 / v0.13:

- both Native (`src/control-surface/service.mjs`) and the Advanced Console
  (`src/admin/api.mjs`) already delegated outbound writes to a single
  `createOutboundConfigService` (`channel:<type>:outbound`, canonical) in the production assembly;
- inbound writes already used one `createInboundChannelConfigPort`
  (`<type>:account`) shared by both adapters;
- connectivity test already went through the same injected `channelTest`.

What was missing: a single **application service** owning channel write/test orchestration. The
orchestration was duplicated between the two adapters, and `src/admin/api.mjs` still carried a
latent legacy writer (`admin:channel:<type>:outbound`, and a fallback inbound port) for callers
that inject no canonical service.

### Work done

Added `src/control-plane/channels.mjs` — `createChannelControlService({ outboundConfig, inboundConfig, channelTest, saveInbound, removeInbound })`.
It owns orchestration only (save/remove outbound, save/remove inbound, test); it wraps the two
existing authorities and never becomes one (I1). Inbound save normalizes a non-durable result
into a `storage-failed` error (I2/I16).

Wired:

- `src/index.mjs`: one `channelControl` instance injected into both `createControlSurfaceService`
  and `createAdminApi`.
- `src/control-surface/service.mjs`: `channels.save` / `channels.test` now call the shared service;
  it constructs an equivalent instance from legacy deps when none is injected (test/back-compat).
- `src/admin/api.mjs`: `putOutboundChannel` / `deleteOutboundChannel` / `testOutboundChannel`
  canonical branches call the shared service; error-code mapping (422/404/500, 501 for
  not-configured) preserved. The pre-v0.13 legacy branch (only reachable when no canonical service
  is injected) is unchanged.

Added tests: `test/channel-control-service-v014.test.mjs` (6 cases) —

1. Native and Admin share one writer → same canonical key, no legacy dual-write, alternating
   field-level writes do not stale-overwrite;
2. real filesystem persist failure (state file under a regular-file parent) → `storage-failed`,
   neither memory nor runtime publishes;
3. durable success + runtime apply failure → `saved:true`, `applied:false`, `restart-pending`,
   desired already on disk;
4. canonical beats legacy overlay on conflict;
5. inbound save converges on the same canonical port; persist failure → `storage-failed`;
6. test orchestration reads canonical raw only; unconfigured → `not-configured`.

### Authority / Mutation order / Failure semantics

- Authority: unchanged — outbound desired config stays in `outbound-config.mjs`; inbound config
  stays in `inbound/channel-config.mjs`. The new module is orchestration only.
- Mutation order: validate (in the authority) → durable commit → runtime apply → settlement result;
  unchanged, now reached through one entry.
- Failure semantics: persist failure publishes nothing and reports `storage-failed`; apply failure
  keeps desired and reports `restart-pending`. Not hidden (I16).

### Tests cannot detect / still assumed

- No real provider hot-apply: the runtime swap is exercised against `OutboundSource` only.
- The legacy `admin:channel:<type>:outbound` writer still exists for pre-v0.13 callers that inject
  no canonical service. Production never reaches it, but it remains a latent second write domain;
  recorded in `docs/v0.14-assumptions.md` (A-006) and left for the S12/S15 convergence pass.
- Inbound orchestration is shared through the port but the Native path enters via the service while
  Admin enters the port directly; both target the same instance.
