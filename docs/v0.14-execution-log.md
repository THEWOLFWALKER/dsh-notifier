## S02 — Members / Pairing shared service

`src/inbound/identity.mjs`, pairing `src/inbound/pairing.mjs`), but the **orchestration** lived

### Pre-state found on dev

Session/routing orchestration lived entirely inside the Advanced Console adapter

- `getBindings` / `putBindings` read/derived the two binding tables locally, and `putBindings`

  directly, with adapter-local `hasSession` / `controlSummary`.

There was no shared application service, so the (future) Native Session / Advanced Bindings
surfaces (S08/S09) would have had to re-implement the same projection and write orchestration —
the same I1/I9 duplicate-writer risk S01/S02 closed for channels and members.

### Work done

Added `src/control-plane/sessions.mjs` — `createRoutingControlService({ router, registry, store, warn })`.
It owns orchestration / projection only and composes the three existing routing authorities
(it never merges them, I1):

- session lifecycle stays in `src/routing/session-registry.mjs`;
- routing / outbound overrides stay in `src/routing/agent-router.mjs`;
- control-overlay normalization stays in `src/control/session-arbiter.mjs`.

Methods: `bindingsSnapshot()`, `replaceBindings({ agents?, channels? })`, `sessionIds()`,
`hasSession(id)`, `resolveOutbound(...)`, `sessionsView({ enabledTypes })`,
`patchSessionOutbound(id, diff)`, `patchSessionControl(id, diff)`; plus the exported
`controlSummary(control)` redaction helper (single source for the safe overlay summary).

Crucially the projection does **not** reintroduce the historical `route:sessions` whole-table
stale-cache overwrite: every write goes through the router setters, which merge the field-level
diff (I10, anti sibling-clobber). A failed durable commit is surfaced as `storage-failed`; the
adapters must report failure, never success (I2/I16).

> **Corrected in S03-P1 remediation (below).** The original S03 text claimed the router setters
> "re-read the latest store table and merge before write". That double-read still left a TOCTOU
> window between the second read and the real `store.transact()` commit, so a concurrent writer
> could still be clobbered. See the remediation section for the fix; the merge now happens *inside*
> the transaction mutator.

Domain primitive added in `src/routing/agent-router.mjs` (v0.14 S03):

- `snapshotBindings()` — copy-on-read snapshot of both binding tables;

  a legacy store without `transact` degrades to two single-key writes but returns an honest

The whole-table normalization (`normalizeAgentsTable` / `normalizeChannelDefaultsTable`) was
extracted from the pre-existing `replaceAgentBindings` / `replaceChannelDefaults` into reusable

Wired:

  sites stay in the adapter. The now-unused adapter-local `readTable` / `registrySessionOf` /

## S03-P1 remediation — session overlay TOCTOU (in-transaction merge)

### Finding (external review of `dev`)

`src/routing/agent-router.mjs` `setSessionOutbound()` / `setSessionControl()` computed the new
`route:sessions` table **outside** the store transaction: they read the table, then re-read a
"latest" copy, merged the field-level diff onto that copy, and only then called
`writeMap()` → `setDurable()` → `store.transact()`. Because the real transaction re-reads the
disk and runs its mutator on a fresh draft, the outer "latest" snapshot the mutator re-installed
was already stale: between the outer re-read and the commit a concurrent writer could change
another field of the same session, and the whole-record write-back would clobber it.

Reproduced for `setSessionOutbound` (a concurrent `control.owner` change was overwritten back to
the pre-read value) and for `setSessionControl` (a concurrent `outbound` change was overwritten).

### Fix

Extracted a `commitSessions(mutate)` helper used by both setters:

- when the store has `transact`, the **read of the newest table and the record-level merge happen
  inside the transaction mutator** (`draft[KEY_SESSIONS]` in, new table out), so the commit base is
  the transaction's own fresh draft — no stale whole-record write-back (I3/I10);
- when the store has no `transact` (legacy/mock), it degrades to the previous single-key
  read-modify-write (single-process best-effort; atomicity is not faked).

Patch-shape validation and normalization stay outside the transaction so invalid input still throws
`TypeError` synchronously (contract unchanged); only the state-dependent merge moved inside.

### Tests added (`test/agent-router.test.mjs`, 2 cases)

`makeTxStore` — an in-memory store with real `transact` semantics — wraps `transact` so a
concurrent write is injected immediately *before* the real mutator runs:

1. `setSessionOutbound` must preserve a concurrently written `control.owner` (old code reset it to
   the stale value);
2. `setSessionControl` must preserve a concurrently written `outbound` (old code reset it).

Both cases fail against the pre-fix code and pass after it.

  `safeCall` wrapper so a throwing getter degrades that one field instead of failing the snapshot.
- Snapshot fields: `version` (plugin version), `process.epoch/revision`, `host` (host capability

- Truth rules enforced in code: `unknown != failed` (a read failure → `unknown`, never

- Redaction: the final snapshot body is passed through `redactDiagnosticValue` (defence in depth),

- `src/control-surface/service.mjs`: optional `diagnostics` dependency; `diagnostics.snapshot`
  returns `{ …revisionView(), …snapshot }` and — being read-only — does **not** touch revision and
  records **no** activity. Without the dependency it falls through to the unknown-method
  `bad-request` (old callers/tests unchanged).
- `src/index.mjs`: assembles one `createDiagnosticsService` over the live singletons (version read

### Authority / Mutation order / Failure semantics

- Authority: none — diagnostics is explicitly **not** an authority and holds no state. It only reads

- Mutation order: not applicable (read-only). The RPC method is a pure read: no revision touch, no

- Failure semantics: any read that throws/returns nothing degrades to `unknown`/empty for that
