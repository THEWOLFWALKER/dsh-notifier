# dsh-notifier v0.14 External Evidence Matrix

This matrix tracks what automated tests can and cannot prove for the v0.14 workstream. Real
device / provider evidence is **non-blocking** for this workstream (see
`docs/v0.14-architecture-contract.md` §7). A missing external check is recorded as
`external-evidence-pending`; it is never faked, and it is never re-described as a higher level.

Evidence level vocabulary (do not invent others, do not promote by wording):

```text
unit-tested
contract-tested
source-verified
host-smoke-verified
provider-verified
real-device-verified
external-evidence-pending
```

Issue #26 and the other device/provider items above stay **open**. "Looks fixed in code" does
not flip any of them to `real-device-verified`.

The authoritative, longer-lived list of provider/device gaps lives in
`docs/memory/risks.md`; this matrix is the v0.14 workstream view and links back to it.

## What tests cannot prove (standing)

- a mock may implement an official API that does not exist;
- a provider mock may accept a payload the official endpoint would reject;
- unit tests may not simulate a late response;
- a mock store may never fail;
- a test fixture may always be a single writer;
- a UI test may assert `0` where the real value is unknown;
- a synthetic Host may provide every service at once, hiding a real inject / capability gap.

Each stage review must list its own "tests cannot detect / still assumed" items.
