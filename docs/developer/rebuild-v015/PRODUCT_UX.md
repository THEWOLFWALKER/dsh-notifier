# 产品与 UX 决策：Native-first，私聊专用

## 产品原则

dsh-im 是竞品基准，不是功能清单。比较用户完成任务的成本与可信度：几步完成连接、是否知道权限何时生效、待办能否找到、错误能否自救、发送证据是否可信、账户切换是否明确。dsh-notifier 的差异是聚焦通知和私聊控制；不追群聊、多机器人堆叠或旧控制台。用户文案只讲行动与结果，内部术语（Worker、Tunnel、secretReference、generation、accountId、RPC、入站控制）不进入用户界面。

## 核心旅程与验收

| 旅程 | 用户看到/完成什么 | 危险状态与恢复 | 竞品对照维度 |
|---|---|---|---|
| 首次开通知 | 选择渠道，填最少凭证，预览将收到哪类通知；保存后可测试 | 只设通知绝不开私聊；测试返回“已送出请求/已确认/暂无法确认/未发出” | dsh-im 配置步数、清楚程度 |
| 开私聊 | 独立“开启私聊”；可复用 Telegram Bot Token，默认一账号；确认本人后选择任务 | 开启失败不显示已开；身份未确认不允许控制；未知 chat type 拒绝 | 接入完成率、首条消息到任务成功率 |
| 关私聊 | 点击关闭后界面即显示“正在关闭/已停止接收指令”；可继续接收通知 | 关闭过程中封锁新指令；停止失败显示需要处理，不撒谎称已停 | 撤销权限所需时间与可验证性 |
| 多 owner / 账号 | 默认只展示当前身份；有歧义时让用户选择明确的渠道/身份 | 不默取第一个 owner；操作前服务端再核对；内部 ID 不展示 | 身份可理解性、误操作率 |
| 处理问题和审批 | 待办总数准确，置顶需处理；“稍后处理”仍留在待办，可再找回 | 已被别人处理显示事实，不记本次成功；过期清楚说明 | 找到待办、处理时间、误拒绝率 |
| 当前任务 | 任务按最近可用/关注排序，能搜索或翻页；选择后可见当前任务 | 超过前 10 个必须能继续找；无 workspace 不露 taskRef | 选择成功率、长列表可达性 |
| 渠道健康 | 通知和私聊分别显示；“配置好/连接中/需要处理/结果待确认” | 数据读取失败显示“暂时无法读取”，给重试；不显示“尚未配置” | 故障诊断所需步骤 |
| 连接 Cloud | 一个主按钮、可选自定义地址；平台内部细节藏到诊断 | 确定失败给重试/新建，结果不明给核对；显示可能保留云资源 | 自动连接成功率、恢复时长 |
| 成员管理 | Native 可查看、更改、移除使用者及撤销配对码；危险动作有目标与后果确认 | 无唯一当前身份时先选择；最后 owner 不能误删；错误保持原状 | 日常管理可达率 |
| 诊断/恢复 | 日常操作留 Native；高级入口仅只读诊断和恢复说明 | 旧控制台代码与入口删尽；不暴露内部 CRUD | 自救率、支持沟通成本 |

## 信息架构

建议 Native 只保留：概览、通知、私聊、待处理、设置/帮助。概览展示真实需关注事项并提供下一步，不重复铺配置术语。通知和私聊分别有状态；渠道 rail 先按需处理排序，再分页/搜索，不固定截断前 12。待办列表返回 `items,total,hasMore,cursor`，主页使用 total，任何摘要与详情来自同一读模型版本。所有读模型返回 `ready | empty | loading | unavailable | stale` 加时间；只在成功读到空集合时显示“暂无”。

## 微文案与反馈

- `accepted`: “平台已接收，送达尚未确认”；`confirmed`: “已确认送达”；`unknown`: “结果暂无法确认，请先查看对方是否收到”；`failed`: “未发出，可重试”。
- 启用/关闭是状态转换，不在持久化 desired 改变时立刻显示完成；按钮处理中可取消，但取消也必须说明已发生的外部效果。
- “稍后处理”保留待办，可设提醒时间；如果某类问题无法 defer，文案改成明确“拒绝”，不可使用同一标签。
- 不显示 `taskRef/accountId/channelKey` 等内部字段。诊断页可复制脱敏的支持信息，有明确隐私说明。
- 表单验证在提交前提示用户可修复内容；服务端权威校验仍必须存在。方向、渠道、空 key、重复账号均明确报错。

## UX 研究与门禁

在 S0 固定 6 个核心任务的可观测基线：首次通知、开/关私聊、多 owner 选任务、处理待办、Cloud 恢复；记录点击数、错误恢复率、误解点。S3 用真实 DSH host 的桌面明暗主题和手机窄屏走查，至少一名不熟内部实现者完成任务。DOM 自动化覆盖真实可见字符串与状态转换；词汇 lint 读取渲染文本和 i18n 资源，不限某种源码拼接模式。无真实宿主证据标 unknown，不能把 fixture 截图作通过。

## 旧版退出

删除旧 Advanced Console 的整套前后端实现与资源。仅在确有诊断必要时留下重新审定的最小只读 Recovery 入口；否则同样删除独立服务。旧版接口、旧 UI、旧文案不作为兼容目标。已有状态只做安全备份并引导重设；新架构不为少数旧状态牺牲权限边界与 UX。
